# ACVM 수학 명세

설계서 §2·§4·§7의 모든 수식이 코드 어디에 있고, 어떤 테스트가 그 값을 고정하는지 정리합니다.
숫자는 모두 `tests/unit/test_quant.py`가 매 빌드마다 다시 계산합니다.

## 1. 수익 엔진 (§2) — `acvm/quant/economics.py`

| 식 | 의미 | 설계서 예시값 → 코드 결과 |
|---|---|---|
| `E[R] = I · CTR · CVR · AOV · r` | 게시물 1건 기대 수수료 | — |
| `RPI = CTR · CVR · AOV · r` | 노출 1회당 수익 | 0.008·0.03·30,000·0.03 = **0.216원** |
| `EPC = CVR · AOV · r` | 클릭 1회당 수익 | **27원** |
| `I* = C_unit / RPI` | 손익분기 조회수 | 150 / 0.216 = **694.4회** ("약 700회") |
| `Π = ΣE[R] − N·C_unit − C_fixed − L_invalid − T` | 시스템 순이익 | `system_profit()` |

**운영 KPI 1순위**: 채널 중앙값 조회수 ÷ I*. 값이 1 이상이면 콘텐츠를 늘릴수록 이익이 선형 이상으로 커집니다.

### G3 채널 확장 게이트 (§11) — `channel_admission()`

- 점추정: 로그정규 적합(로그값의 중앙값·MAD) → `median ≥ I*`이면 확장
- 신뢰구간: `median ∈ exp(μ̂ ± z·σ̂/√n)`. `require_lower_bound=True`이면 하한이 I*를 넘어야 통과합니다. 운 좋았던 첫 달 하나로 채널이 확장되는 것을 막습니다.
- 표본이 30건 미만이면 판단을 보류합니다(확장 안 함).

## 2. 꼬리 분포 (§2.2) — `acvm/quant/distributions.py`

조회수는 `I ~ LogNormal(μ, σ)`로 모델링합니다.

| 항등식 | 코드 | 검증값 (σ = 2) |
|---|---|---|
| `E[I] = median · e^{σ²/2}` | `LogNormal.mean` | **7.389배** ("약 7.4배") |
| 상위 q의 몫 `S(q) = 1 − Φ(Φ⁻¹(1−q) − σ)` | `top_share()` | 상위 1% → **37.2%**, 상위 5% → **63.9%** |
| `P(I ≥ t) = 1 − Φ((ln t − μ)/σ)` | `sf()` | Monte-Carlo 20만 회와 ±1% 이내 일치 |
| `E[I \| I > t] = E[I]·Φ(σ − z)/(1 − Φ(z))` | `conditional_mean_above()` | Monte-Carlo와 ±5% 이내 일치 |

설계서의 "상위 1~5%가 수익 대부분"을 정량화하면 이렇습니다. σ=2에서 상위 5% 콘텐츠가 전체 조회수의 64%를 만듭니다.

### 시도 횟수 (§2.2 원칙 1)

- `P(n번 중 상위 q가 1개 이상) = 1 − (1 − q)^n` → q=1%, n=100: **63.4%**, n=300: **95.1%**
- `n* = ⌈ln(1 − p)/ln(1 − q)⌉` → 95%를 보장하는 최소 시도 수: **299**

## 3. 상품 기회 점수 POS (§4 M1) — `acvm/quant/features.py`, `modules/m1_product/pos.py`

```
POS = w₁·log(1+reviews) + w₂·rating + w₃·𝟙rocket + w₄·f_price(p) + w₅·r_cat + w₆·V_demo + w₇·M_trend + w₈·EPĈ_bayes − λ·P_risk
```

- 피처는 모두 [0,1]로 정규화한 뒤 가중합합니다. 양의 가중치 합은 1이라서 `min_pos = 0.7`이 "만점의 70%"라는 일관된 의미를 가집니다.
- `f_price`: 1만~5만 원 구간은 1.0, 구간 밖은 로그가격 공간에서 가우시안으로 감쇠합니다(σ=0.6). 5천 원이면 0.51입니다.
- 쿠팡 검색 API는 평점과 리뷰 수를 주지 않습니다. 비어 있는 값은 카테고리 사전값으로 채우고 `features.imputed`에 기록해서, 근거 없는 정밀도를 만들지 않습니다.

### EPC 축소추정 (Empirical Bayes) — `bayes.shrink_epc`

```
EPC_bayes = (revenue + κ · EPC_prior) / (clicks + κ),   κ = 50
```

클릭 3번에 2,700원을 번 신상품의 원시 EPC는 900원입니다. 축소추정하면 **76원**으로 내려가 검증된 상품보다 위로 올라가지 못합니다(설계서의 "신규 상품 과대평가 방지").

## 4. 학습·최적화 (§4 M10) — `acvm/quant/bayes.py`

arm = (카테고리, 훅 유형, 템플릿, 페르소나, 플랫폼, 시간대). 보상 모델은 세 단계 켤레(conjugate) 모델입니다.

```
clicks | I      ~ Binomial(I, CTR),         CTR ~ Beta(α, β)
orders | clicks ~ Poisson(λ·clicks),        λ   ~ Gamma(a_λ, b_λ)
수수료/주문      ~ Exponential(θ),            θ   ~ Gamma(a_θ, b_θ)   (평균 1/θ)
RPI = CTR · λ · (1/θ)
```

- **갱신**: 세 사후분포 모두 O(1)로 갱신됩니다. 관측은 `arm_observation`에 게시물 단위로 저장하고 *증분*(새 값 − 이전 값)만 사후분포에 더합니다. 켤레 계수는 덧셈 구조라서 재수집이나 재시도가 일어나도 정확히 멱등입니다.
- **계층적 사전분포**: 새 arm은 부모(카테고리×플랫폼) 사후평균을 중심으로 κ=20개 콘텐츠 분량의 사전 증거를 받습니다(partial pooling). 무정보 사전분포에서 출발해 과도하게 탐색하는 것을 막습니다.
- **Thompson Sampling + 탐색 예산 20%**: 생산 슬롯의 ⌈0.2n⌉개는 *젊은 arm*(시도 30회 미만)에 Thompson으로 배정하고, 나머지는 모든 활성 arm에 `샘플 RPI × 기대 조회수`로 배정합니다. 테스트에서 탐색 슬롯 20개가 정확히 젊은 arm에만 가는 것을 확인합니다.
- **퇴출**: 30회 이상 시도한 arm 중 사후평균 EPC가 하위 10%면 탐색 대상에서 제외합니다.
- **증폭**: 게시 후 48시간 안에 같은 플랫폼 조회수 백분위가 98% 이상이면 변형 5개를 만들고 아직 게시하지 않은 플랫폼에 교차 배포합니다.
- **플레이북**: 요인별 RPI lift의 사후 확률 `P(lift > 0)`을 Monte-Carlo로 추정합니다. 0.9 이상이고 표본이 10건 이상이면 숫자를 포함한 자연어 규칙으로 기록합니다.

## 5. 유사도 (§4 M2/M4, §8.1 R-02·S-01) — `acvm/quant/similarity.py`

한국어는 교착어라 공백 토큰이 조사 때문에 서로 어긋납니다. 그래서 모든 비교는 NFKC 정규화와 공백·구두점 제거를 거친 **문자 n-gram**으로 합니다.

- **R-02 n-gram 중복률**: `|grams₅(후보) ∩ grams₅(참조)| / |grams₅(후보)| > 0.15` → 재생성
- **R-02 코사인**: 임베딩 코사인 > 0.80 → 재생성 (pgvector `<=>`, 개발 환경에서는 해싱 임베딩)
- **S-01 MinHash**: 128개 순열, 4-gram shingle. `E[일치율] = Jaccard`, 표준오차 `√(J(1−J)/128) ≈ 0.043`(J=0.6일 때)
- **LSH 밴딩**: `P(후보) = 1 − (1 − s^r)^b`. FP·FN 가중 적분을 최소화하는 (b, r)를 고르며, 놓친 중복이 더 비싸므로 FN 가중치를 3배로 둡니다.
- 비교 텍스트에서는 **대가성 문구를 제외**합니다(`repos.similarity_text`). 모든 게시물에 똑같이 들어가는 문구가 유사도를 지배하지 않게 하기 위해서입니다.

## 6. 쿼터·스케줄 (§7) — `acvm/quant/ratelimit.py`, `scheduling.py`

- **이중 강제**: 실효 상한 = `min(계정 일일 상한, ⌊API 한도 × 0.30⌋)`. Threads는 min(20, 75) = 20, TikTok은 min(3, 4) = 3입니다.
- **24시간 이동창**: 정확한 sliding-window log(Redis ZSET + Lua 원자 연산)를 씁니다. 같은 게시 토큰으로 다시 요청하면 슬롯을 새로 먹지 않고 성공을 반환합니다(멱등).
- **쿠팡 검색 예산**: 토큰 버킷(용량 8, 초당 8/3600 충전). 403이 오면 서킷이 열리고 1시간 동안 캐시로 운영한 뒤 **단 1회** 탐침합니다.
- **층화 지터 스케줄**: 시간창을 n개 층으로 나누고 층 중심 ±7분 균등 지터를 줍니다. 정각 ±3분은 피하고, 최소 간격 20분을 지키며, 용량이 넘치면 다음 날로 넘깁니다. i.i.d. 균등 배치보다 뭉침이 적고, 고정 그리드처럼 매일 같은 분에 올라가지도 않습니다.

## 7. 이상 탐지·계정 위험 (§4 M9, §7.1) — `acvm/quant/anomaly.py`, `risk.py`

- **CTR 급등**: 과거 CTR 사후분포 Beta(α, β) 아래에서 오늘 클릭 수는 **Beta-Binomial 예측분포**를 따릅니다. `P(K ≥ k)`를 정확히 합산합니다(정규근사는 CTR 1% 근처의 꼬리를 크게 과소평가합니다). 기준은 p < 10⁻⁴입니다.
- **클릭 버스트**: 해시된 IP 하나가 같은 링크를 60초 안에 3번 넘게 누르면 무효 클릭 의심으로 판단하고 링크를 일시 중지합니다.
- **쿨다운**: "실패율 10% 초과" 규칙은 사전분포 Beta(1, 9)에서 `P(실패율 > 10% | 데이터) > 0.8`로 바꿔 판정합니다. 3번 중 1번 실패(33%)로는 발동하지 않고, 40번 중 10번 실패는 발동합니다. 도달률이 7일 중앙값 대비 −60% 이하이거나 플랫폼 경고가 오면 즉시 48시간 쿨다운입니다.

## 8. 특수함수 — `acvm/quant/special.py`

SciPy 없이 순수 Python으로 구현했습니다. 정규화 불완전 베타 `I_x(a,b)`는 Lentz 연분수, 역함수는 안전장치를 둔 Newton/이분법, 하부 불완전 감마, Beta-Binomial 로그 pmf입니다. 정수 a, b에 대해서는 항등식 `I_x(a,b) = P(Binomial(a+b−1, x) ≥ a)`와 10⁻¹²까지 일치하는 것을 테스트로 고정합니다.
